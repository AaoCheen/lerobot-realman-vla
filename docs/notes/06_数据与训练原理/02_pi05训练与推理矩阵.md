# 02：π0.5究竟在训练什么

## 1. 先分清三个时间轴

| 符号 | 含义 | 本次例子 |
|---|---|---|
| `r`、`h` | 真实轨迹起点、块内未来时刻 | `h=0…49`，每行是一个未来动作 |
| `τ` | flow matching的噪声时间 | `τ≈0`靠近数据，`τ=1`为纯噪声端 |
| `k` | 优化器更新次数 | 日志`step=3500`等，最大54075 |

**流场对`τ`的“速度”，不等于关节角度对物理秒的速度。** 最后给机器人的仍是关节位置目标，不是训练流场本身。

下面用`B`表示每卡batch，本次`B=2`；`H=50`；真实动作维`D=7`；内部动作维`D_pad=32`。

## 2. 条件输入如何编码

本次模型可概括为：视觉/语言主干处理当前图像与任务/状态文本，动作expert处理带噪动作，二者通过联合注意力交换信息。不是两个互不通信、最后才简单拼接的网络。

### 图像路径

```text
global: [B,3,480,640] ─┐
                      ├─ 各自缩放并补边到224×224、范围变成[-1,1]
left:   [B,3,480,640] ─┘
                        ↓ SigLIP视觉编码器＋投影
                     图像token序列
```

这不是预测视频。输入是当前两路RGB画面。图像token与后面的文字token组成prefix。

### 状态和文字路径：本实现把状态写进prompt

训练集分位数统计对状态和动作分别归一化。对第`d`维：

```text
z_d = 2 × (x_d - q01_d) / (q99_d - q01_d) - 1
```

实际实现对近零分母有保护。`q01`和`q99`是该维训练值的1%与99%分位数，**状态和动作各有一套统计**。数值不保证严格落在`[-1,1]`，本机这个归一化分支没有自动裁剪两端离群值。

状态处理链：

```text
原始关节/夹爪 [B,7]
  → 分位数归一化 [B,7]
  → 补零 [B,32]
  → 按[-1,1]上的256个bin离散化
  → 拼成任务＋状态文字
  → tokenizer
```

prompt形如：

```text
Task: pick up the plug and place it in the box, State: 128 91 ...;
Action:
```

这里的整数只是示意，不是本次样本的真实token值。32个离散状态整数也不等于32个token：整数文本会再经过tokenizer。

本次tokenizer输出ID和mask均为`[B,200]`，超长截断、短则补齐。这个`Action:`标记不代表训练时把未来真实动作写进prompt；真实动作单独走标签/带噪动作分支。

π0.5这条路径不再单独把连续state送入一个state projection。数值状态通过上述文本条件进入模型。与其他策略或其他π0实现不要混淆。

### 动作路径

```text
原始标签Y [B,50,7]
  → 训练集动作分位数归一化
  → 补零为X [B,50,32]
  → 加噪得到X_τ [B,50,32]
  → action_in_proj: 32 → 1024
  → 动作token [B,50,1024]
```

当前`gemma_300m`动作expert的隐藏宽度1024；视觉/语言`gemma_2b`文字侧隐藏宽度2048。联合注意力负责让动作token在当前图像、任务和状态条件下建模。

`τ`先经过正弦/余弦编码和time MLP，再通过AdaRMS条件调制动作expert。`τ`告诉网络这个动作块当前处于多大噪声程度，而不是告诉它“现在训练到第几步”。

## 3. 训练：随机挑一个噪声时刻，监督一个速度场

对每个样本抽取：

```text
ε ∼ Normal(0,I)                  形状 [B,50,32]
τ = 0.999 × Beta(1.5,1.0)+0.001  形状 [B]
```

每个样本一个`τ`，广播为`[B,1,1]`，用于它整块50×32动作；不是给每个元素各抽一个噪声时间。噪声`ε`则是整个张量逐元素抽样。

定义干净动作`X`与噪声间的直线：

```text
X_τ = (1-τ)X + τε
U_τ = dX_τ/dτ = ε-X
```

网络接收条件`C`、带噪动作`X_τ`和`τ`，预测：

```text
V_θ = v_θ(C, X_τ, τ)      [B,50,32]
```

动作expert输出`[B,50,1024]`，再经`action_out_proj:1024→32`得到上面的流场。训练目标是让预测流场接近已知的`U_τ`。

本机`PI05Policy.forward`最终把逐元素损失裁到前7维，再平均：

```text
L = 1/(B×50×7) × Σ_b Σ_h Σ_(d=0…6)
                         (V_θ[b,h,d] - (ε-X)[b,h,d])²
```

补齐的25列不是25个额外电机，不参与最终loss平均。它们只是模型统一接口的内部维度。

**训练有随机加噪，也在学习如何沿流场回到数据；但一次训练forward不需要从纯噪声连续迭代10次。** 当前训练对随机`τ`做一次流场预测，算MSE，然后反向传播更新参数。gradient checkpointing会在反向时重算部分forward，那是省显存的计算技巧，也不是10步采样。

用一个标量说明符号方向。假设某个归一化动作元素`X=0.4`、抽到`ε=-0.6`、`τ=0.7`：

```text
X_τ = 0.3×0.4 + 0.7×(-0.6) = -0.3
U_τ = -0.6 - 0.4 = -1.0
```

这个训练点要求网络预测约`-1.0`，不是直接预测`0.4`。推理是从`τ=1`向`τ=0`走，时间步长为负，所以方向会反过来；这与恢复干净动作一致。

## 4. 一次optimizer step怎样发生

当前训练入口的实际顺序：

```text
DataLoader读取本卡2个样本
 → pre(batch)：归一化、状态prompt、tokenizer、移到GPU
 → optimizer.zero_grad()
 → model(batch)：图像编码＋随机加噪＋流场预测＋MSE
 → 所有rank检查loss是否有限
 → backward()
 → FSDP同步/分片梯度，计算全模型梯度范数并裁剪到1.0
 → 检查梯度是否有限
 → AdamW更新参数
 → scheduler更新学习率
 → step加1，按频率写日志/保存
```

四卡全局batch=8，没有梯度累积。所有参数可训练，包括视觉侧和语言/动作侧；不是LoRA，也不是只训动作头。FSDP FULL_SHARD切分模型参数、梯度和优化器状态；前向/反向用BF16，训练主参数保持FP32。

在本机模型中部分联合注意力绕过整个decoder层的`forward`，所以入口对实际调用的独立Linear设置FSDP单元，当前457个。切得细会增加通信次数；gradient checkpointing还会增加重算。这两者都是训练耗时的来源，4卡不意味着单步必然快4倍。

训练默认返回的是`(标量loss, loss_dict)`；记录的loss是当前全局batch流场MSE，不是部署动作，也不是抓取成功率。当前循环没有调用`select_action`驱动机器人。

## 5. 推理：这时才从噪声开始做10步积分

部署时没有未来动作标签`X`，只有当前条件`C`。因此：

```text
初始 X_1 = ε                        [B,50,32]
Δτ = -1/10 = -0.1

τ=1.0:  X_0.9 = X_1.0 - 0.1 v_θ(C,X_1.0,1.0)
τ=0.9:  X_0.8 = X_0.9 - 0.1 v_θ(C,X_0.9,0.9)
 ...
τ=0.1:  X_0.0 = X_0.1 - 0.1 v_θ(C,X_0.1,0.1)
```

这是本实现的Euler积分，视觉/语言prefix可先算好KV cache，多次动作expert调用复用条件。不要把这里的10步理解成训练10个optimizer step。

采样结束后：

```text
内部动作块             [B,50,32]
 → 截取前7列           [B,50,7]       predict_action_chunk返回
 → 选前10行动作队列    [B,10,7]       select_action内部
 → 每次取一行动作      [B,7]          select_action每次返回
 → postprocessor反归一化
 → 去掉batch维         [7]            单机器人部署常见形式
 → 转换为SDK关节位置/夹爪命令
```

反归一化公式：`x=(z+1)×(q99-q01)/2+q01`。推理调用方必须执行处理器；只调用裸模型得到的还是归一化空间中的动作。

三个容易混淆的配置：

| 配置 | 本次值 | 控制什么 |
|---|---:|---|
| `chunk_size` | 50 | 训练标签和生成动作块有50行 |
| `n_action_steps` | 10 | 使用标准select_action队列时，执行前10行后重新观察、生成 |
| `num_inference_steps` | 10 | 生成一个动作块要做10次流场积分 |

当前训练loss覆盖全部50行，并非只训前10行。若部署程序直接调用`predict_action_chunk`并自行调度，执行多少行由部署程序控制，不能仅凭训练配置断定真机一定按10步重规划。

## 6. 到源码里看哪些函数

在`.venv/lib/python3.11/site-packages/lerobot/`下：

| 文件/函数 | 关注点 |
|---|---|
| `datasets/factory.py::resolve_delta_timestamps` | 未来动作索引如何换成秒 |
| `policies/pi05/configuration_pi05.py::action_delta_indices` | `0…49` |
| `processor/normalize_processor.py` | 分位数归一化/反归一化 |
| `policies/pi05/processor_pi05.py::Pi05PrepareStateTokenizerProcessorStep` | 状态补齐、离散化、写进任务prompt |
| `policies/pi05/modeling_pi05.py::PI05Policy.forward` | 入口预处理、7维loss裁剪 |
| `PI05Pytorch.forward` | `x_t`、`u_t`、流场预测、逐元素MSE |
| `PI05Pytorch.sample_actions` | 从噪声开始、负步长Euler积分 |
| `PI05Policy.predict_action_chunk/select_action` | 裁回7维和动作队列 |

可以对照[官方v0.4.3模型代码](https://github.com/huggingface/lerobot/blob/v0.4.3/src/lerobot/policies/pi05/modeling_pi05.py)与[状态处理器代码](https://github.com/huggingface/lerobot/blob/v0.4.3/src/lerobot/policies/pi05/processor_pi05.py)。上文公式、实际维度和loss裁剪已逐项核对本机安装源码。
