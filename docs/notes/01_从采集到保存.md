# 01 从采集到保存：先认清一条示范是什么

## 1. “一条数据”指什么

本项目通常把**一次完整示范称为一个 episode／一条轨迹**，其中有几百个时间步（帧）。例如 `realman_new` 有47条轨迹、26372帧，不是26372次抓取。单帧记录同一时刻附近的相机图像和机器人状态，配一个动作标签及任务文本。

采集时由人遥操作或拖动机器人，**无需先训练 π0.5**。采集决定记录什么；LeRobot 负责组织训练数据；策略模型之后学习从观测生成动作。

## 2. 先看同学实际版本，再看公开模板

当前新仓库是公开模板；`../../../lerobot-realman-vla-history/` 是复制来的同学版本，两者的采集流程有差异。下面以 history 的实际代码为主做静态追踪，不能证明所有历史数据都由这一版源码生成。

```text
collect_data.py: main()
  ├─ SDK 连接 RM65，初始化夹爪、顶部与腕部相机
  ├─ ViveController / PikaGripperTeleop：人操作，独立线程让设备跟随
  ├─ DataRecorder：独立线程，目标30Hz记录实际状态和图像
  └─ CollectorController.action_toggle_record()
        ├─ 开始：DataRecorder.start() → _record_loop() → 内存缓冲
        └─ 停止：stop() → _save() → 一条 HDF5
              └─ 若开启 auto-convert：后台队列 → LeRobotAsyncConverter
                    → _read_hdf5() → _open_dataset()
                    → 每帧 add_frame() → save_episode() → finalize()
                    → Parquet + MP4 + meta
```

关键阅读位置（相对当前仓库，点开后可按函数搜索）：

| 步骤 | 代码位置 | 看什么 |
|---|---|---|
| 入口与参数 | [history collect_data.py](../../../lerobot-realman-vla-history/scripts/collect_data.py)，`main()`，约1299行起 | fps、task、auto-convert、输出路径、设备初始化 |
| 人遥操作 | 同文件 `ViveController`，约300行起；`PikaGripperTeleop`，约590行起 | 控制机械臂/夹爪的线程，与记录线程不同 |
| 采样 | 同文件 `DataRecorder._record_loop()`，718行起 | 关节反馈、夹爪缓存、相机帧、时间戳进入缓冲 |
| 保存 | 同文件 `DataRecorder._save()`，754行起 | 动作标签、HDF5字段、图像压缩 |
| 自动转换 | 同文件 `LeRobotAsyncConverter`，816行起 | 从HDF5转换、帧写入、视频与元数据收尾 |
| 手动转换 | [history convert_to_lerobot.py](../../../lerobot-realman-vla-history/scripts/convert_to_lerobot.py)，`main()` | 已有一批HDF5如何离线生成新数据集 |

history 默认按 `s` 开始/停止保存，`w` 控制遥操作开关；实际按键表可能覆盖默认值。这些用于理解代码，不是当前8卡机的实机操作指令。

## 3. 每一帧里有什么

| 字段 | 实际含义 |
|---|---|
| `qpos` / `observation.state[:7]` | `[J1,J2,J3,J4,J5,J6,gripper]`，关节绝对角度单位为度，夹爪归一化0闭1开 |
| 两路图像 | 顶部全局图＋腕部图；采集接口给BGR，history转换时显式转RGB |
| `ee_pose`（可选） | 控制器反馈的末端 `[x,y,z,rx,ry,rz]`，米／弧度，独立字段 |
| `timestamps` | 原始HDF5记录的实际相对采样时间，不是相机硬件曝光时间戳 |
| `task` | 转换时提供的一段任务文本；同一转换批次可能统一赋值，文件名不能证明内容与标签一致 |
| `action[t]` | **代码保存的是下一帧实际状态 `qpos[t+1]`，末帧重复最后状态；不是直接保存下发控制命令** |

这个动作定义已在全部4个RM65数据版本中验证：每条轨迹除最后一帧外，`action[t] == state[t+1,:7]`，最大绝对差为0；5条现存HDF5也一致。它是下一时刻关节位置目标形式的监督，不是角度增量、速度或力矩。

这也解释了动作和状态统计为什么相近，不能仅凭相近就认定“不看图”。模型训练时再按所选策略的数据索引规则组装未来动作块；原始采集本身不是直接保存 `50×7` 的动作块。

## 4. 两种落盘形式

### 原始HDF5：一条示范一个文件

```text
observations/qpos                    [T,7]
observations/ee_pose                 [T,6]（可选）
observations/images/camera_global    [T,480,640,3]
observations/images/camera_left      [T,480,640,3]
action                               [T,7]
timestamps                           [T]
```

当前保留5个HDF5，仅是现存原始文件，不代表只采了5条，也不能直接当作训练集以外的5条新示范。

### LeRobot v3：状态表、视频和索引分开

```text
data/datasets/数据集名/
├── meta/info.json             # 机器人类型、维度、帧率、规模、路径模板
├── meta/tasks.parquet         # 任务文本与 task_index
├── meta/episodes/...parquet   # 每条轨迹的长度、文件映射、视频起止时间和统计
├── meta/stats.json            # 数据集统计，用于归一化等
├── data/...parquet            # 每帧 state、action、timestamp 和索引
└── videos/相机名/...mp4       # 图像转成视频
```

**episode编号、Parquet文件编号、MP4文件编号不保证相同。** 当前 `realman_merged` 多条轨迹共用Parquet；SO100的50条示范每相机共用一个长视频。读取必须按 `meta/episodes` 映射与视频时间段定位，不能按MP4个数数轨迹。

history转换没有把原始 `timestamps` 传给 `add_frame()`；当前Parquet时间步均匀为1/30秒。它不能替代原始采样抖动检查。5条HDF5实际平均约30Hz，最长相邻间隔约47.8ms；图像与关节读取也不是硬件同步，后台相机最新帧可能存在延迟。

## 5. `realman_all` 的10维从哪来

它不是10轴机械臂：前7维仍是机器人，后3维为图像处理得到的 `[r,dx,dy]` 插头相对位置特征。全局图裁成400×400，腕部图裁成320×320。后处理脚本涉及裁剪、去掉尾部、追加位置特征、删集和合并；每一步的确切历史参数仍需日志确认。

本次逐帧匹配确认：95条的前7维状态与动作，分别对应 `realman_new` 的47条和 `realman_new_after48_full` 的48条完整轨迹或前缀。说明是派生版本，不能当新增95次采集，也不能与原版分别放进训练和验证集。图像处理来源未逐像素核对。

## 6. 已确认的代码风险与版本差异

- **history自动转换存在数据丢失风险**：`LeRobotAsyncConverter._loop()` 的 `finally` 中，只要 `delete_hdf5=True` 就删除HDF5，**转换失败也删除**。构造默认开启删除。后续采集应先修成成功且验证后再删，或先禁用自动转换保留原始HDF5；本次没有修改源码或运行采集。
- 状态读取失败时，history记录线程会用全零关节和末端位姿兜底，错误可能变成训练样本。当前4个RM65数据版本没有检出六关节同时为零的帧，但未来采集应明确记录失败并丢弃无效帧。
- 新仓库转换器读取的是 `cam_high/cam_wrist`，同学现有HDF5键是 `camera_global/camera_left`，**直接用新模板重转会读不到键**。
- 新模板直接把BGR交给PIL、末尾用 `consolidate()`；history显式BGR→RGB并用 `finalize()`。应先按锁定LeRobot版本对齐接口，不能混用两套脚本。
- 原始采集是7维；10维是后处理结果。训练10维时部署必须用一致的ROI、位置估计与标定，不能给7维输入。

以上为源码静态追踪＋本地数据检查，未在真实设备上验证采集循环或遥操作。
